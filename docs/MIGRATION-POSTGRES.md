# PostgreSQL

The platform moved from Node's built-in SQLite to PostgreSQL. This page explains what changed, how the database layer
behaves, the rules for new code, and how to move an existing SQLite deployment.

## Running it

| Where | What to set |
| --- | --- |
| Local | `DATABASE_URL=postgres://user:pass@localhost:5432/mouldcare` (or `docker compose up -d db` with `POSTGRES_PASSWORD` in `.env`) |
| Docker Compose | `POSTGRES_PASSWORD` in `.env`; compose starts PostgreSQL and passes `DATABASE_URL` to the platform |
| Render | The Blueprint creates `platform-db` and links it; see [DEPLOY-RENDER.md](DEPLOY-RENDER.md) |
| Tests | `DATABASE_URL` pointing at any database the user can create schemas in, then `npm test` |

With `NODE_ENV=production` the server refuses to start without `DATABASE_URL`. `DB_POOL_MAX` sets connections per
instance (default 10). Add `?sslmode=require` to the URL for a database reached over the internet.

## What changed

- **Schema.** `backend/migrations/000_baseline_postgres.sql` is the schema and reference data produced by the 17
  SQLite migrations, generated by `backend/scripts/schema2pg.mjs`. The originals are kept in `migrations/sqlite-legacy/`
  for history. New changes go in `003_*.sql` onwards. Foreign keys are `DEFERRABLE INITIALLY IMMEDIATE`: checked on
  every statement as before, but the importer can defer them to the end of its transaction.
- **`001_sqlite_compat.sql`** keeps three SQLite idioms working with identical results: `datetime('now')`,
  `json_extract(doc, '$.path')`, and `round(float, n)`. Prefer native PostgreSQL in new queries.
- **`002_insertion_order.sql`** adds a `seq` column where code relied on SQLite's hidden `rowid` for ordering
  (checklist entries, assistant messages, vision events).
- **`common/db.js`** keeps the same API (`one`, `all`, `run`, `transaction`, `id`, `now`) but every call is async.
  `run()` still returns `{changes}`. `?` placeholders still work; they are rewritten to `$1…$n`.
- **SQL dialect.** `INSERT OR IGNORE` → `ON CONFLICT DO NOTHING`; `INSERT OR REPLACE` → `ON CONFLICT (key) DO UPDATE`;
  `LIKE` → `ILIKE` (SQLite's LIKE ignores case); `x IS ?` → `x IS NOT DISTINCT FROM ?`; `group_concat` → `string_agg`;
  `json_each` → `jsonb_array_elements_text`; keyword aliases (`hour`) now use `AS`.
- **Scripts** (`seed`, `bootstrap-admin`, `iot-sync`, `ml-export`) close the connection pool when they finish.

## How requests use the database

SQLite was synchronous, so every request handler ran from start to end without any other request interleaving. The
code depends on that (check-then-insert, counters, deduplication). The server keeps the same guarantee:

| Request | Runs in | Why |
| --- | --- | --- |
| POST, PUT, PATCH, DELETE | `transaction()`: one connection, one transaction, a writer lock | Same atomicity as SQLite; a failure rolls the whole request back |
| GET | `readOnly()`: a read-only, repeatable-read snapshot | Consistent data, and reads run in parallel (SQLite could not) |
| Routes marked `{external:true}` | no wrapper; each statement commits on its own | They wait on AI or remote services; holding the writer lock for seconds would block everyone |
| Offline-replay routes | `transaction()` plus the replay record | Unchanged behaviour |
| Background jobs | each tick in `transaction()` | Same as requests |

Measured locally: 100 simultaneous writes and 100 simultaneous reads on one ticket finished in 0.7 s, with exactly 100
rows and 100 audit entries, no errors and no lost writes.

The writer lock is global, which matches SQLite's single writer. If write volume ever needs it, the next step is a lock
per company (`pg_advisory_xact_lock(hashtext(company_id))`).

## Rules for new code

1. **Await every database call**, and every function that calls one: `const t = await one(...)`. A missing `await`
   does not crash: the value becomes a Promise, which shows as `{}` in JSON or silently passes a check
   (`if (!promise)` is never true).
2. **No async callbacks in `.map` / `.filter` / `.forEach` / `.some` / `.find` / `.reduce` / `Array.from`.** Use the
   sequential helpers from `common/db.js`: `mapSeq`, `filterSeq`, `forEachSeq`, `someSeq`, `everySeq`, `findSeq`,
   `flatMapSeq`, `reduceSeq`. They keep order and side effects exactly as the synchronous code had them. This includes
   passing a function by name: `.map(T.unitView)` must be `await mapSeq(rows, T.unitView)`.
3. **No database calls in default parameter values** (`function f(x, p = one(...))`). Look the value up in the body.
4. **A GET route that writes** (audit log, raising an alert) needs `{writes:true}`:
   `r.get('/path', handler, {writes:true})`. Otherwise PostgreSQL rejects the write in the read-only snapshot.
5. **A route that waits on something outside the database** (AI, HTTP, a long computation) gets `{external:true}`.
6. **Write PostgreSQL SQL**: `COALESCE` not `IFNULL`, `GREATEST`/`LEAST` not two-argument `MAX`/`MIN`,
   `SUM(CASE WHEN … THEN 1 ELSE 0 END)` not `SUM(condition)`, `AS` before aliases, and quote camelCase aliases
   (`AS "totalQty"`) because PostgreSQL lowercases unquoted names.
7. Timestamps are still ISO-8601 text, as before, so string comparison keeps working. Converting them to `timestamptz`
   is a separate, later change.

## Bugs found during the move

These were hidden by synchronous SQLite and would have appeared on PostgreSQL. The tests caught four; the rest came
from reading code paths the tests don't reach.

| Area | Problem | Effect |
| --- | --- | --- |
| Vision licences | Seat count computed in an un-awaited inline function | Camera licence limits not enforced |
| Equipment specs | Same-company check passed as a callback, not awaited | Equipment could be linked across companies |
| Traceability routes | Module imported as `T`, about 36 calls not awaited | Traceability endpoints returned unfinished results |
| Traceability lists | `.map(T.unitView)` / `.map(T.shipmentView)` | Label, pallet and shipment lists showed empty rows |
| Offline replay | Handler result not awaited before saving | Replay record stored an empty object |
| Plant service area | Validator passed into `keep()` | Updated plants stored an empty object |
| Demo seed | `Array.from(..., async ...)` | Label boxes created as Promises |
| Scripts | Open connection pool | `bootstrap-admin`, `iot-sync`, `ml-export` would never exit |

## Moving an existing SQLite deployment

```
DATABASE_URL=postgres://… node backend/scripts/import-sqlite.js /data/mouldcare.sqlite
```

- Refuses a SQLite file that is missing any of the 17 legacy migrations (start the last SQLite release once first).
- Refuses a PostgreSQL database that already has companies, unless `--force`.
- Copies every table in one transaction, in original insertion order; all foreign keys are checked before commit.
- Verifies row counts per table at the end.
- Uploaded files are not in the database: copy `MOULDCARE_DATA_DIR/uploads` across (on Render they are already on the
  same disk).

Tested on a database created by the SQLite version (demo seed plus simulator history): 30,863 rows across 63 tables,
counts matched, and the app ran on the imported data with no errors on any screen.

## Verification done
